# ADR-0008 — Demo interactiva: modo offline con StatefulFakeLLM y fixtures de muestra

| Campo       | Valor                  |
|-------------|------------------------|
| Estado      | Aceptado               |
| Fecha       | 2026-06-23             |
| Autor       | victorlr94             |

## Contexto

El MVP (Fases 0-6) es técnicamente completo pero no es demostrable sin fricción:
- El CSV de Kaggle y el modelo `.pkl` están gitignoreados (voluminosos, derivados).
- La demo requiere `ANTHROPIC_API_KEY` y consume créditos por cada llamada.
- Un reclutador clonando el repo necesita descargar Kaggle, entrenar y configurar
  una API key solo para ver el agente en acción.

**Meta:** URL pública donde en <30s, sin clave, se vea propensión, EV, HITL y el
mensaje final del agente.

## Opciones consideradas

| Opción | Pros | Contras |
|--------|------|---------|
| **Demo offline + fixtures commiteadas** (elegida) | Sin Kaggle, sin API key, deploy trivial, reproducible | Binarios pequeños en git (~900 KB total); modelo demo tiene menos datos |
| Usar el modelo completo + API key en HF Secrets | Demo más fiel al sistema real | Requiere clave de pago; reclutador no puede probar sin autorización |
| Generar datos sintéticos en arranque | Sin binarios en git | Lento en cold-start en host gratuito; no reproduce el CSV real |
| Entrenar en el arranque del servidor | Siempre datos frescos | ~60s de arranque en HF Spaces; usuarios ven pantalla en blanco |

## Decisión

**Modo demo offline** con dos componentes:

### 1. StatefulFakeLLM (ya existente en `evaluation/fake_components.py`)

Simula determinísticamente el loop ReAct del agente (`query_propensity →
select_best_offer → mensaje final`) sin llamada de red. El truco clave:
`human_gate` en `graph.py` dispara `interrupt()` basándose en el EV calculado
por las tools del modelo real, no por el LLM. Por tanto con `StatefulFakeLLM`
se obtienen **propensión real, EV real y HITL real**.

### 2. Fixtures commiteadas

- `data/sample/telco_sample.csv` (121 KB): 500 filas estratificadas del IBM Telco
  dataset con `make_sample.py`. El churn rate se conserva (~26.6%).
- `models/demo/lgbm_demo.pkl` (769 KB): `LightGBMChurnModel` entrenado sobre el
  sample. Mismo pipeline de Fase 2 (`train_lgbm + calibrate`).
- Total: ~890 KB — aceptable para un repo de portafolio; menor que una imagen PNG
  de captura de pantalla.

Allowlists en `.gitignore`:
```
!data/sample/
!data/sample/*
!models/demo/
!models/demo/*.pkl
```

### 3. App Streamlit + HF Spaces

- `src/churn_agent/demo/service.py`: `DemoService` instancia el grafo demo una
  sola vez (singleton en Streamlit vía `@st.cache_resource`) y expone `analyze()`
  y `approve()` espejando `api/routes/agent.py`.
- `src/churn_agent/demo/streamlit_app.py`: UI de una pantalla.
- `app.py` (raíz): shim para Hugging Face Spaces (SDK Streamlit).
- `requirements.txt`: exportado con `uv export --extra demo`.
- Streamlit es dep opcional (`[project.optional-dependencies] demo = ["streamlit>=1.40"]`).

## Consecuencias

**Positivas:**
- Cold-start en <5s en HF Spaces (sin entrenamiento ni descarga).
- Propensión, CLTV, EV, HITL y mensaje final son 100% reales.
- Tests deterministas sin API key (`tests/demo/test_demo_service.py`).
- Un reclutador puede usar la demo desde incógnito sin configurar nada.

**Negativas:**
- El modelo demo tiene 500 filas de entrenamiento vs. 4 225 del modelo de producción
  → métricas algo inferiores (AUC-ROC ~0.77 vs. ~0.85).
- Binarios pequeños en git: regla habitual es evitarlos, pero el trade-off de
  simplicidad de deploy justifica la excepción para un portafolio.
- Si el CSV de Kaggle se actualiza, hay que regenerar las fixtures y re-commitear.

## Regeneración de fixtures

```bash
# Solo necesario si cambia el CSV fuente o los hiperparámetros del modelo demo
uv run python scripts/make_sample.py
git add data/sample/telco_sample.csv models/demo/lgbm_demo.pkl
git commit -m "chore: regenerar fixtures de demo"
```
