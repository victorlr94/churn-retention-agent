# ADR-0003: LightGBM como modelo de propensión al churn

## Estado
Aceptado

## Contexto
El dataset IBM Telco (~7 000 filas, ~27% churn) requiere un modelo que:
1. Maneje datos tabulares mixtos (numéricos + categóricos) sin preprocesado extenso.
2. Sea robusto al desbalance de clases (73% / 27%).
3. Produzca scores calibrables a probabilidades reales (necesarias para el cálculo de EV económico).
4. Genere explicaciones por feature (SHAP) para alimentar al agente en Fase 3.
5. Se entrene en segundos en CPU local (dataset pequeño).

## Decisión
Usar **LightGBM** (`LGBMClassifier`) como modelo principal, envuelto en un sklearn Pipeline con:
- `ColumnTransformer` para preprocesado de features mixtas.
- `CalibratedClassifierCV(cv="prefit", method="isotonic")` para calibración post-entrenamiento.
- Evaluación comparativa contra dos baselines (mayoría + regresión logística).

## Alternativas consideradas
- **XGBoost**: rendimiento similar en tabular, pero más lento en entrenamiento y requiere tuning más cuidadoso de `scale_pos_weight`. LightGBM con `class_weight="balanced"` lo maneja automáticamente.
- **Random Forest**: menor riesgo de sobreajuste, pero peor AUC-PR en datasets desbalanceados y sin soporte nativo de SHAP TreeExplainer optimizado.
- **Regresión logística (solo)**: interpretable y rápida, pero supone linealidad; usada como baseline, no como modelo principal.
- **CatBoost**: manejo nativo de categoricals sin encoding, pero dependencia más pesada y menor ecosistema de SHAP.

## Consecuencias
+ LightGBM + SHAP TreeExplainer es la combinación de mayor rendimiento/explicabilidad en tabular con CPU.
+ `class_weight="balanced"` evita preprocesado extra de imbalance (SMOTE, etc.) para el baseline.
+ El modelo queda detrás del `ChurnModel` Protocol: se puede sustituir sin tocar el agente.
- La calibración isotónica requiere un conjunto de validación separado (~20% del train); con 7 000 filas el conjunto de calibración es pequeño (~1 000 filas) — suficiente para isotónica pero no para Platt con muchos parámetros.
- LightGBM no distribuye stubs de tipo: se requiere `ignore_missing_imports = true` en mypy y `strict=false` para `churn_agent.model.*`.
